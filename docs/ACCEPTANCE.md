# 手动验收清单

建议先复制本轮结束约定，随普通测试任务一并发送，再开始以下验证；之后再测试 Work。不要直接把重要项目当作首个验证场景。

| 操作 | 预期 |
| --- | --- |
| 正在回复时写草稿并启用 | 保持等待，不中断当前轮次 |
| 回复中途停顿／工具执行 | 不因文字暂时停止而发送 |
| 出现最后回答完成按钮且本轮口令匹配、输入框可用 | 连续稳定观察后发送一次 |
| 启用后修改草稿 | 自动暂停，要求重新启用 |
| 启用后新增／删除附件 | 若该附件组件被识别，暂停 |
| 附件显示上传进度 | 等待，不发送 |
| 带一个无敏感信息的小 PDF 启用草稿发送 | 确认用户消息同时包含正文和附件；不重复上传 |
| 带 XLSX／图片分别测试 | 验证该界面附件选择器有效 |
| 队列启动前输入框有手写草稿 | 拒绝启动，不覆盖 |
| 两条文字队列 | 第一条发出后必须等待新的回答，第二条不会连续发出 |
| 点击暂停 | 后续尚未发生的点击停止，原有任务继续由 ChatGPT 执行 |
| 切换对话／项目 | 停止运行，切换到该对话自己的队列 |
| 刷新页面 | 任务保留，运行默认暂停 |
| 同一对话开两个标签页 | 第二个标签页不能在第一个运行时启动 |
| 点击发送后刷新或网络异常 | 结果不明时保留锁定，不自动重试 |
| 存在错误或确认弹窗 | 自动发送暂停 |
| 无法识别完成按钮 | 等待并显示原因，不能用总耗时替代完成判断 |
| 标签页后台放置 30 分钟，再恢复 | 重新观察状态，不沿用休眠前倒计时 |

## v1.1 严格结束约定专项

- 没有为当前任务设置结束约定时，拒绝启用。
- 中途文字带复制按钮、发送按钮可用、长时间无变化，但没有本轮口令时，保持等待。
- 旧口令、其他对话口令、代码块或引用口令不能触发发送。
- 口令后面还有其他文字时，不放行。
- 最后回复身份或正文在倒计时／发送前发生变化时，停止沿用旧观察结果。
- 本轮被手动停止、页面出现非最终通道、离线或标签页隐藏时不发送。
- 草稿修改后立刻改回，也必须重新启用。
- 一条队列发出后，下一条必须等待新口令；不能复用旧回答。
- 页面恢复可见或超过 5 秒没有采样时，重新开始稳定观察。

## Work 专项

需要记录：界面类型、浏览器版本、普通回复和工具运行中的 DOM 信号是否不同，以及是否存在“中间步骤也带完成按钮”的结构。若有误判可能，应增加显式 Work 运行信号，或在适配前禁用该界面的自动发送。

当前版本没有完成这项真实登录页面验收。不应把离线夹具测试通过宣传为 Work 已兼容。
