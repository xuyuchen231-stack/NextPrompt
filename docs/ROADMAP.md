# 路线与自动规划设计

以下内容是计划，不代表当前已有远程服务或 API 自动执行功能。

## v1：先可靠发送用户指定的下一步

已实现原生草稿单次发送、文字队列、附件原位保留、手动启停、本地保存和发送核验。后续优先完成真实 Work 界面适配、更多附件组件夹具、无障碍与发送回执优化。

## v2：本地面板与远程投递

先做桌面本地任务服务，再考虑手机页面或微信小程序。

| 能力 | 必需条件 |
| --- | --- |
| 本地提交文字 | 浏览器连接、明确对话 ID、任务去重 ID |
| 本地提交文件 | 文件选择授权、受控临时目录、文件与任务绑定、上传回执 |
| 手机远程投递 | 设备配对、HTTPS 或受控隧道、短时凭证、文件传输、撤销机制 |
| 状态查看 | 区分接收、传输、上传、页面发送、模型完成五种状态 |

远程提交不应假装电脑永远在线。离线时标记等待，重连后按任务 ID 去重。文件收到不等于已发送给 ChatGPT，附件错误应阻断对应任务。

## v3：能够解释依据的下一步规划器

目标：根据实际进展提出少量高价值任务，避免无限“继续优化”。

输入应包含：用户目标、验收标准、约束、任务历史、经用户选择的对话摘要、最新输出和实际证据。代码项目尤其需要变更摘要、测试结果、未解决问题，而不是只读最后一句回答。

规划器建议返回：

```json
{
  "decision": "suggest",
  "goal_status": "partial",
  "evidence": ["相关测试尚有一个失败，错误记录可复现"],
  "remaining": ["导出数据单位仍需确认"],
  "next_prompt": "只修复已复现的单位换算问题，并运行对应测试。",
  "acceptance": ["换算结果与基准一致", "相关测试通过"],
  "stop_reason": null,
  "needs_user": false
}
```

允许的决策应为 `suggest`、`stop`、`ask_user`。先将建议展示给用户，点击后加入队列；经实际评估后才考虑限定自动执行。

### 深度与质量

- 建立项目事实记录，防止重复修改和遗忘约束。
- 要求每个下一步对应一个尚未满足的验收条件。
- 不让规划模型仅凭执行模型的“已完成”声明判定成功。
- 比较候选下一步的收益、依赖和验证成本，最终只选最有价值的一项。
- 目标完成、缺少关键上下文、连续无进展、达到轮次或费用预算时停止。
- 规划质量需要真实任务集评估；不能通过“多思考一会”承诺深度。

### API 与网页能力的边界

API 规划器是另一个独立客户端，不自动继承当前网页的全部历史、项目文件或连接工具。需明确选择发送哪些上下文；API 账单和账户可用额度需要独立确认。Key 应保存在本地后端或操作系统凭据管理器，不写入扩展源码、导出任务或仓库。

可能采用 Responses API 的文件输入、对话状态和后台执行能力，但具体接口、模型和费用须在实施时核验官方文档。当前版本没有这部分可执行代码，也不需要提供 Key。

官方参考：

- https://developers.openai.com/api/docs/guides/file-inputs
- https://developers.openai.com/api/docs/guides/background

### 自动化不应越过用户决定

建议支持最多轮次、最大费用、限定对话、禁用事项、暂停按钮和用户决定节点。涉及发布、删除、权限或付费等动作时，应遵守相应平台的确认要求；规划器不能把“持续改进”理解为无限授权。
